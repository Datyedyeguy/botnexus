## Summary

Automatically normalize legacy SQLite tool transcript rows after upgrade without delaying gateway startup or requiring repeated debug commands. A delayed hosted worker commits bounded batches through the same migration authority as the existing CLI command and resumes naturally from durable row linkage after restart.

Refs #4526

Remaining issue scope: payload cleanup and projection parity; configured hot/warm/cold retention and protected-evidence policy; physical SQLite copy/validation/replacement reclamation; progress and operator controls; crash-boundary coverage across cleanup, retention, and replacement; and documentation remain owned by #4526.

## Changes

- Move the legacy tool-invocation backfill into the session-store project so CLI and runtime automation share one implementation.
- Add a SQLite-store entry point that commits one bounded normalization transaction.
- Run automatic backfill after a one-minute startup delay in batches of 100 rows, with a one-second inter-batch delay and a five-minute retry after contained failures.
- Make non-SQLite session stores inert and honor host cancellation during startup, pacing, and retry delays.
- Preserve the existing preview-by-default CLI behavior and explicit `--commit` mutation contract.

## Anti-reinvention

The change reuses the normalized `tool_invocations` schema, `session_history.tool_invocation_id` durable checkpoint, the merged PR #4486 transaction and pairing logic, `SqliteSessionStore`, and the gateway hosted-service composition seam. Current source, repository conventions, merged PR #4486, and all open pull requests were checked. The hosted driver is new because the existing command is operator-invoked and the save-time reconciliation path does not sweep dormant legacy rows; no second migrator or progress store is introduced.

## Risk & rollback

- Blast radius is SQLite session-store startup maintenance. The worker waits one minute, mutates at most 100 legacy rows per transaction, yields between batches, and contains ordinary failures for later retry. Non-SQLite stores are unchanged.
- This slice links normalized records only. It deliberately does not delete transcript payloads, transition retention state, or reclaim/replace database files.
- Revert the commit to remove automation and restore the CLI-owned source location. Already-linked rows remain compatible and idempotently excluded from future backfill.
- Test changes are additive and retain all CLI assertions; no assertion, skip, timeout, threshold, or baseline was relaxed.
