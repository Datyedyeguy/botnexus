## Summary

Add the authenticated human review boundary for persisted agent proposals. Administrators can list, inspect, approve, reject, and reconcile proposal applications; approvals use the shared agent lifecycle service, while rejection leaves configuration and the registry unchanged and records a durable notification for the proposer.

Closes #4093

## Changes

- Add authenticated administration endpoints for proposal list, detail, review, and explicit reconciliation of interrupted applications.
- Extract the existing create/update agent lifecycle into a shared service used by both direct administration and approved proposals, preserving validation, registration, provisioning, notifier, and compensation behavior.
- Claim application attempts atomically, persist reviewer/decision/reason/outcome data, prevent repeated application, and require explicit reconciliation after ambiguous interrupted or compensation-failure states.
- Deliver rejection feedback through the proposer’s durable conversation/session transcript rather than a logging-only delivery placeholder.
- Add schema migration support for application state and reconciliation evidence, including populated v1 migration coverage.
- Document authorization, application, rejection, failure, retry, and rollout-disabled semantics.

## Anti-reinvention

The implementation reuses `IAgentConfigurationWriter`, the existing registry, provisioner and notifier seams, persisted proposal storage, conversation/session stores, and the established authenticated administration policy. The direct `AgentsController` lifecycle was extracted rather than duplicated, so proposal approval and direct administration share the same validation and compensation path. Current source and open pull requests were checked before publication; no open pull request owns this issue’s proposal-review slice.

## Risk & rollback

- Blast radius includes authenticated agent administration, proposal persistence migration, lifecycle compensation, and durable rejection notification. Review rollout remains disabled until the proposal-tool and bypass-restriction prerequisites are available.
- Interrupted or ambiguously compensated applications fail closed and require explicit evidence-backed reconciliation before retry, avoiding an automatic second application.
- Revert the feature commit and synchronization merge to remove the review surface and shared proposal application flow. Existing proposal rows remain readable only by schema versions that understand the added application columns, so rollback across an initialized v2 store requires the usual data-backup and migration discipline.
- Test changes add authorization, lifecycle, idempotence, migration, and recovery assertions; none were relaxed to obtain green.

## Merge notes

This change depends on the persisted proposal contract from #4092 already present on `main`. It adds a schema-v2 migration for the proposal store but no package dependency or enabled rollout switch. The review surface remains under the existing authenticated human administration boundary. Passing validation does not authorize merge; human authorization remains required.
